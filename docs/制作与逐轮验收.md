# 《桃源寻码》制作与逐轮验收

状态：已通过 PINOC 生成并下载渔郎骨骼高斯角色、桃花山谷和三组定制动作；取得四种免费库动作。已建立本地连续剧情与固定机位检查预览，实际进度见 preview/README.md 与 reviews/迭代记录.md。本文后续条目包含待实施要求，不应视为全部完成。

## 场景分层
远景桃花山谷交由 PINOC 场景生成：连绵浅玉色山体、桃红山谷、远端桃源村、日光薄雾；保持明亮、开阔、可辨认的溪流走向。以已生成全景为视觉参考，生成时核对实际输入能力。输出格式、尺度、碰撞、编辑与渲染支持以实际工具返回为准。

近景由可控场景资产组成：可行走小路、流动小溪、桃树、木桥、任务交互点。几万簇草、雏菊、薰衣草、蕨类采用分块实例化、距离裁减和简化层级，避免每簇独立对象。首轮目标为共 30000 簇，性能验证后调整；这是待验证预算，不是已达到的性能数据。草与雏菊布置于溪岸和路缘，蕨类集中在阴湿树下，薰衣草作为村口人为栽种的花圃。保留道路边缘与任务物件视线。

统一风场驱动草叶、花与树梢，叠加位置相位差；蓑衣、围巾运动需单独核验。不可预设生成的高斯角色自带可用布料模拟。远景与近景统一太阳方向、色温、雾与接缝遮挡。

## 角色与动作
输入素材：渔郎三视图.png（正、侧、背同一张联幅）。若 PINOC 支持多图输入，再按其要求准备独立视图；不默认三视图输入一定输出带骨骼高斯角色，提交前核对生成模式、骨架、动作绑定和导出能力。

动作库检索：走、跑、挥手、点头。优先使用同一骨架兼容动作；核对脚底滑动、位移、循环接缝、斗笠遮挡与围巾穿模。记录原始动作 ID 和角色绑定后的结果 ID。

文字动作需求：
- 坐下吃饭：角色平稳坐到矮凳，身体微前倾，左手端碗，右手持筷夹菜并送到嘴边，动作轻柔，结束回到坐姿待机。需要碗、筷、凳子的相对位置与手部接触核验。若工具仅生成身体运动，道具与手指另行制作，不把它误判为完整成片。
- 作揖：站立、双手在胸前合拢作传统拱手礼，上身轻轻前倾，再回到原位；自然克制，双脚稳定。核对双手关系，不以普通鞠躬代替。
- 小孩蹦跳：用于独立村童角色；原地轻快地双脚小跳两至三次，屈膝缓冲，手臂自然摆动，开心但不过度夸张，回到站姿。村童尚无设定和模型，先登记动作需求，不把成人渔郎的缩放当成已完成村童。

## 每轮执行规范
R00：保留现有概念图作为参考，不能称为游戏实机截图。
R01：先完成地形、路网、角色尺度与交互点，六机位截图，对照 14 周路线检查是否存在学习入口缺失。
R02：调整山谷与近景接缝、光线、桃林遮挡；保留相机不动，截图并排比较。
R03：加入分区植被和风场，记录实际实例数、帧时间、显存/内存；以实测决定密度，截图验证道路和物件仍可读。
R04：接入角色与七类动作，固定机位截图加短片，核查脚底、道具、关节和穿模。
R05：串起学习任务，从 W1 到 W14 逐项检查；本轮若仅有三关原型，应明确其余为未实现，不以地图上的建筑代替完成课程。

每轮目录 `reviews/Rxx/` 保存：六机位截图、路径对照页、差距记录、改动清单、复验结果与性能记录。每个差距写“目标 / 截图或运行证据 / 差距 / 下一轮改动 / 复验结果”。没有实际运行证据的条目标待验证。

验收优先级：阻断学习或运行的错误 → 任务和路径辨认 → 角色与动作正确性 → 性能与风动 → 视觉细节。每轮先记录问题，再修改，再从同一机位重新截图，禁止移动相机掩盖问题。
