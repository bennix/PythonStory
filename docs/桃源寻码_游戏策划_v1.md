# 《桃源寻码》Python 自学游戏策划 v1

## 1. 一句话概念
你是一位戴竹斗笠、披稻草蓑衣、系桃红长围巾的渔郎，沿溪进入桃源，用 Python 帮村民解决真实的小问题；最终离开提示和熟悉的题面，独立写出、解释并验证自己的程序。

本版为游戏策划与视觉开发提案，尚未实现游戏程序。面向零基础自学者，采用单人探索、代码解谜、村落建设反馈的形式。以桌面端键盘输入为主要交互，建议先制作网页原型。

## 2. 依据与改编边界
依据当前目录 `output/python_ai_selfstudy/main.tex` 的课程目录、练习与模拟题。按用户确认移除 HTTP API 与 LLM/伦理两项，保留其余内容与先后顺序，压缩为 14 周路线，不强行拆成五个教学章节。

原文意象“缘溪行 → 忽逢桃花林 → 山有小口，仿佛若有光 → 豁然开朗，桃源村 → 处处志之，不复得路”作为空间与情绪线索，可以跨周出现、反复返回。归途不表示学习失败，而表示不能靠记住旧题路线解决新问题。

改编任务必须保留原项目要求与数学关系。例如 BMI 仍用于身高体重记录，月供仍用于现代借贷计算，不把这些概念牵强改成古代生产规则。它们可作为漂流来的“异乡任务册”出现。

## 3. 学习目标与核心循环
沿用手册三条能力主线：读得准、写得出、验得了。

一次任务循环：探索发现问题 → 写清输入/处理/输出 → 预测一个例子的结果 → 输入代码 → 运行并观察世界反馈 → 用普通、边界、反例验证 → 用自己的话解释 → 隔日换题重做。

场景变化只是运行结果的可视化，程序是否正确由明确的输入输出与用例判断。不能只靠走到终点、点选正确按钮通关。

每日 60 分钟建议：10 分钟回忆昨日问题，15 分钟学习一个概念，25 分钟写程序与验证，10 分钟记录错因。完整运行、失败记录、解释和重测结果进入“行囊手记”。

## 4. 课程与关卡路线
| 周 | 原课程内容与项目 | 游戏任务 | 通关证据 |
|---|---|---|---|
| 1 | 环境、IPO、祝福程序 | 溪畔启航：输入名字，让渡口灯牌显示祝福 | 从空白写输入输出；解释三步数据流 |
| 2 | 类型、表达式、BMI、时间换算 | 航程小账：换算行船时长；异乡册 BMI 支线 | 单位表、类型说明、正常与边界用例 |
| 3 | Prompt、AI 代码验证 | 桃林问路：检查引路伙伴给出的三份有问题的建议 | 三次失败与修正日志；每次有反例 |
| 4 | 调试、异常 | 修补渡船：辨认语法、运行时、逻辑三类错误 | 各修一例并说明原因；阶段独立测验 |
| 5 | 分支、循环、嵌套、猜数字、计数 | 桃林试灯：猜灯号；按条件点亮一排灯 | 循环跟踪表、精确输出、终止条件 |
| 6 | 列表、元组、成绩管理 | 初入村塾：录入成绩、求平均、筛选 | 空列表等边界行为明确；解释下标与别名 |
| 7 | 字典、集合、更新删除、去重 | 村塾名册：以学号管理成绩，统计与去重 | 重复学号规则、计数字典、多键排序 |
| 8 | math/random/string/re，随机号码、邮箱、月供 | 驿站来信：提取邮箱、生成号码；异乡册月供 | 解释匹配规则；命中与不命中样例；库函数边界 |
| 9 | 参数、lambda、map/filter、薪资函数 | 工坊分工：把薪资与统计需求写成小函数 | 参数与返回值约定；循环与函数式结果对照 |
| 10 | 模块、入口、跟踪、重构成绩管理 | 众匠协作：把村塾工具整理为模块 | 导入不意外启动交互；能解释执行顺序 |
| 11 | 文件、CSV/JSON、异常、问卷、日志脱敏 | 桃源档案馆：问卷保存读回；给日志脱敏 | 读—洗—写链路；输入不存在与写失败分别处理 |
| 12 | Pandas、清洗、汇总、简单图表 | 丰收账房：清洗样例 CSV 并汇总展示 | 缺失值处理有依据；筛选条件正确；图表吻合数据 |
| 15 | 输入—处理—保存综合项目、答辩、模拟 A | 桃源共建：完成可运行的村塾成绩工具 | 输入验证、模块、文件、用例与说明；独立模拟 A |
| 16 | 知识图谱、800 字反思、模拟 B、复测 | 辞别与归途：熟悉路标消退，用能力完成新任务 | 独立模拟 B；隔日解释错题并重写核心函数 |

字符串索引、切片、清洗、格式化在第 2—5 周溪畔与桃林任务中逐步插入，之后通过来信、日志与文件任务反复复习，避免目录中的字符串章节被遗漏。标准库任务中的 random 在第 5 周固定目标猜数字通过后再引入。

## 5. 一条持续生长的主项目
保留手册“成绩管理”主线，游戏中对应“村塾名册”。

第 6 周列表存成绩 → 第 7 周字典按学号存记录 → 第 9 周把平均、更新、筛选写成函数 → 第 10 周拆模块 → 第 11 周保存 CSV/JSON → 第 12 周 Pandas 汇总 → 第 13 周完成输入验证、测试与说明。

每次升级沿用旧记录。村塾会增加可用书桌、名册架和统计墙，变化对应确实完成的功能。学习者可以随时回看自己早期版本，解释为什么改动。

## 6. 三个可制作的关卡样例
### 样例 A：溪上时刻（第 2 周，约 15 分钟）
问题：已知航行分钟数，换算为小时、分钟、秒。先展示明确单位，再允许输入；玩家先预测 90 分钟的结果，再编写换算。航船依正确时长移动到下一驿站。

验证：0 分钟、90 分钟与带小数的分钟；是否截断按题目约定。失败时显示实际值、期望值与单位，不用随机扣血惩罚。迁移题换成视频播放速度，衔接模拟 A7。

### 样例 B：桃林试灯（第 5 周，约 20 分钟）
问题：先用固定目标 7 实现最多三次猜数，再添加随机目标。玩家输入数字，灯笼显示偏小、偏大或猜对。执行到哪一行，哪一盏灯就亮起。

验证：首次猜中、最后一次猜中、三次均错；解释 break 与循环 else 的关系。必须先画一次变量跟踪表。修改随机范围属于拓展任务，不阻塞基础通关。

### 样例 C：守护来信（第 11 周，约 30 分钟）
问题：按题目规定的邮箱或编号规则脱敏日志。玩家依次完成匹配规则、单行处理、文件处理，将结果存成新文件。场景显示信件进入、遮盖指定字段、放入新档案盒。

验证：正常匹配、不匹配、过长连续串、保留换行、输入不存在、写入失败。采用手册三函数结构。先跑通原样读写，再补脱敏与异常。不能把成功读写误判为整个任务通过。

## 7. AI 引导与独立能力
引导角色暂定“溪光”，表现为一枚小暖光，在需要时出现，不覆盖渔郎的主体形象。

提示逐层开放：重述题意 → 指出相关概念 → 提供一个反例 → 给局部伪代码。完整参考解放在作答后的复盘中，查看后需做一道新变式，不能直接算独立通过。

早期允许较多引导，中期只在玩家主动请求时提示，后期综合任务先独立提交再复盘。最终独立测验关闭 AI、自动补全与代码模板；保留清晰题面和正常报错。AI 不担任唯一评分器，客观结果用确定用例检查，开放解释采用明确评分条目。

“不复得路”的表现：玩家离开村落再回头，旧路标不再构成可照抄的路线，但手记、错误账本和已完成程序仍保留。新题需要自己拆解，避免把失忆或删档当成长。

## 8. 反馈、进度与验收
不以在线时长、连续签到或美术解锁代替能力。每项技能标记为“见过 / 提示下完成 / 独立完成 / 隔日迁移通过”。失败只增加诊断信息，可以无惩罚重试。

错误账本记录：原预测、实际结果、具体错因、最小反例、修正、隔日重测。优先区分类型、单位、缩进、边界、容器修改与数据格式错误。

结业建议沿用手册：两套未做过的限时模拟均达到 80/100，编程部分至少 28/40，隔日还能解释错题并重写核心函数。这是训练标准，不是学校官方合格线。游戏美术与任务完成率不能替代课程成绩。

## 9. 美术设定
总体：明亮、轻盈、有留白的中国田园童话。借鉴《小王子》的清澈明亮感，以及《风之旅人》《光·遇》的孤身旅行、简洁轮廓和空间尺度；角色与服装采用原创渔郎设计。

主色：天空蓝、米白日光、玉绿色溪水、浅金稻田与桃红点睛。洞口仍透暖光，错误反馈使用温和琥珀色。场景不以阴暗恐怖制造学习压力。

主角：竹编斗笠、层叠金黄稻草蓑衣、米白内衣与宽裤、布鞋、桃红长围巾。斗笠下五官简化；围巾通过风向、动作与构图引导视线，不用长度充当学习分数。

全景：溪流—桃林—山口—村落在一个可理解的地理空间中串联；视线由近景小舟引向远景村落。关键画面：启航、桃林发现、光中山口、村落揭示、归途独立。三视图：同尺度正面、侧面、背面，供后续建模与动画使用。

本轮生成的是概念设定图，不能直接作为已校验的建模蓝图或游戏内资产。三视图进入建模前仍需人工核对斗笠直径、蓑衣层次与围巾连接位置。关键画面联幅用于统一气氛，后续可拆成独立镜头重新生成。

## 10. 界面与技术边界
游玩界面分为场景、代码区、运行结果和可展开手记。场景与文字使用稳定布局；报错可回到对应代码行；提供大字体、减少动态效果与键盘操作。

教学 Python 代码需在隔离运行环境执行，限制时长、输出量、文件范围与网络访问。课程任务使用本地输入、文件与样例数据，不设置 HTTP API、LLM API 或伦理报告关卡。密钥不写入代码、存档或 AI 提示。

先以预制演出呈现程序结果，不让生成式模型实时随意改动地图与评分。AI 服务不可用时，预设提示和任务仍可运行。

## 11. 首个可玩版本范围
先制作“溪上时刻 → 桃林试灯 → 村塾名册”三关，验证输入输出、循环与容器三类任务是否真正促进理解。提供一个连续场景、一个渔郎角色、代码输入与运行反馈、用例检查、手记和独立重做。

首版验收：玩家能从空白完成任务，能解释一个失败案例，次日能解决换情境的同类题；运行超时可终止，刷新后可恢复学习记录。先通过这组验证，再扩展完整 14 周路线。
